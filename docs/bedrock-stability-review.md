# Bedrock stability review

Reviewed September 16, 2026. This is a source and code review, not a diagnosis of a captured failing session or a live AWS benchmark.

## Findings

Bedrock interruptions have several distinct causes. AWS documents account throttling (429), temporary capacity failures (503/529), streaming failures and model timeouts. Its guidance is exponential backoff with jitter; cross-region inference can help capacity where supported. These documents do not establish that Bedrock models are generally less stable than direct-provider models. [AWS troubleshooting](https://docs.aws.amazon.com/bedrock/latest/userguide/troubleshooting-api-error-codes.html), [ConverseStream reference](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_ConverseStream.html).

AWS also documents idle connection drops around 350 seconds through certain VPC/NAT paths. That explanation applies only if the request traverses those network components. SDK and OS TCP keep-alive settings both matter. [AWS connection troubleshooting](https://docs.aws.amazon.com/bedrock/latest/userguide/troubleshooting-api-error-codes.html#ts-connection-timeout).

For Claude 3.7 and Claude 4 inference, AWS recommends SDK read timeouts of at least 60 minutes. This is not a requirement to wait an hour on every silent stream, nor a fix for a harness loop. Blacksite uses signed fetch rather than the AWS SDK, and its stream reader has a five-minute no-data deadline. Extended silent thinking can therefore hit Blacksite's own deadline. [AWS Claude Messages guidance](https://docs.aws.amazon.com/bedrock/latest/userguide/model-parameters-anthropic-claude-messages.html).

## Blacksite audit

- `src/bedrock-client.ts` signs Converse requests, decodes AWS event frames, rejects incomplete frames, and bounds idle reads. `src/agent-session.ts` rejects missing completion events and unfinished blocks, handles exception frames, and routes transient failures through recovery. These protections already exist; this review does not add another retry layer.
- Bedrock Converse and Mantle use different wire protocols. Record which API was selected when investigating a failure; a Converse transport finding does not automatically apply to Mantle.
- Map-note reminders are generated by Blacksite after a successful `end_turn` with outstanding edits. They are not AWS error messages. The current limit is two continuations per unresolved batch; satisfying that batch resets the limit. Further edits, including edits during verification, can create a new batch and more reminders. This is a plausible explanation for repeated interruptions, not proof of the reported session's cause.
- Automatic background compaction can overlap inference. Paused compaction now serializes that work at model-call boundaries. This may reduce simultaneous provider demand, but it is not a demonstrated cure for throttling or transport failures.

## How to distinguish the next occurrence

Capture the model ID, region, Converse/Mantle setting, timestamp, request ID when available, and the nearby execution diagnostics. A five-minute no-data timeout suggests the client idle guard; 429 suggests quotas; 503/529 suggests serving capacity; a missing completion event suggests a truncated stream. Repeated map-note continuation messages instead identify harness behavior. Inspect the intervening edit/note/verification calls to see whether the note budget was reset.

Compare background and paused compaction with the same model, region, and task. Record time to first output, longest silent interval, error code, retries, and map-note continuation count. No private session logs or account telemetry were available for this review, so the specific halt remains unconfirmed.

## New compaction control

Settings → Context → History Compression → Compaction mode offers Background (existing default) and Pause conversation. Pause waits for the compression attempt to settle before the next model request; Stop interrupts that wait. Existing compression timeouts, retries, and failure circuit breaker remain in effect. Provider-side compaction remains a separate feature and takes precedence when configured.
